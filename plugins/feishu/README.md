# 飞书桥插件（可选）

让用户**用手机飞书遥控公司**：给老板发消息指挥、客户直接对话客服机器人、里程碑镜像到群。

> 状态：**0.3.1 生产链路已验证（老板/客服 P2P）；0.4.0 多岗位虚拟路由为 staging（测试版）**。
> 安装使用前请阅读本 README 的「边界与人工闸门」一节。

## 能力

| 能力 | 说明 | 状态 |
|------|------|------|
| 老板机器人 | 手机发消息 = 直接指挥公司 | ✅ 0.3.1 生产验证 |
| 客服机器人 | 客户消息直达客服会话，原路回复 | ✅ 0.3.1 生产验证 |
| 多岗位虚拟路由 | 一个老板 App 内 `/成员名|岗位名 正文` 分发 | ⚠️ 0.4.0 staging |
| 离线保护 | 老板离线时消息暂存，上线补投 | ⚠️ 0.4.0 staging |
| 镜像群 | 里程碑推送镜像到用户飞书群 | 🚧 需人工配置 webhook |

## 安装（用户侧）

1. 老板在会话里调用官方一键接入（`feishu_onboard`），生成一次性确认链接；
2. 你打开链接，**确认一次**（官方授权，应用/权限/事件/WebSocket 全自动）；
3. App Secret 自动走 Windows DPAPI 加密，不会出现在任何日志或聊天里；
4. 等 `connected`，给机器人发「测试」验证收发；
5. 需要客服机器人时，同样流程创建员工机器人（`kind=staff + staffMemberId`）。

## 使用姿势

- 给老板机器人发消息 → 框架按「📱 飞书消息」识别为老板本人指令；
- 给客服机器人发消息 → 消息直达客服会话，客服用系统回复通道原路回复；
- 里程碑节点（成片完成、验收请求等）→ 老板可推送镜像群（需配置）。

## 边界与人工闸门（重要）

1. **权限默认全开**：框架建司时老板与员工机器人默认 `allowGroup=true`（单聊+群聊权限一次到位）。**入群仍是人工操作**：权限只授权，把机器人拉进群必须在飞书桌面端/手机端手动操作，框架不自动入群。
2. **禁止重复授权**：已 connected 的机器人不要再执行一次接入流程（会新建第二套机器人，导致同公司两个同名 bot、路由分叉）；确需改权限时先删干净旧机器人（注册表+凭据+用户端旧会话）再重建。
3. **镜像群 webhook 需手动配置**：来自飞书「自定义群机器人」，在桌面端添加；URL 禁止进入日志/聊天/仓库。
4. **0.4.0 staging 边界**：多岗位虚拟路由、离线补投仍在测试；生产部署请先评估并保留 0.3.1 回退路径。
5. **客服回复纪律**：只用系统回复通道的 `botId/receiveId/receiveIdType`；指定 bot 失败时**不静默换 bot**（显式报错）。
6. **老板单聊回传**：回传必须用入站消息日志中的真实 sender open_id，禁止用客服会话里其他客户 id；桥暂存队列（K>0）时用户侧只看到占位回复，重启后补投。
7. **凭据红线**：App Secret、webhook、Token、Cookie 永不进入仓库、日志、回复。

## 卸载

- 移除插件目录 `plugins/feishu/`；
- 在 Harness 侧禁用/删除对应机器人（保留公司数据，仅断开连接）；
- 重新运行 `scripts\verify.ps1` 确认技能回退到无飞书状态。

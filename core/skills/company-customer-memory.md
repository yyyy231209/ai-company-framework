# 客户记忆（通用三层记忆）——任何对客岗位适用

> **门控**：仅公司模式开启（`company_mode`=on）的会话中作为对客岗位能力使用；未开启时本技能不适用，按普通对话处理。

> **适用**：客服、销售、商务、客户经理……凡是需要**对接多个客户**的岗位，都具备本能力。客户档案数据库、记忆读写纪律、隔离铁律对每个对客岗位一致。

## 一、三层记忆结构（公司级，所有对客岗位共享）

```
<companyRoot>/.dsh/memory/
├─ company.md       ← 公司记忆：近况/业务/项目/报价/政策口径（老板可编辑注入）
├─ general.md       ← 通用记忆：沟通技巧/话术/经验（对客岗位共享沉淀）
└─ customers.db     ← 客户档案数据库（SQLite）：customers 表（档案/备注）+ messages 表（逐条会话）
```

**客户档案按 id 隔离**：`open_id`（私聊）/ `chat_id`（群聊）即客户 id；所有读写都带 customer_id 条件——客户 A 永远读不到客户 B。

## 二、脚本（customer-memory.mjs，node 内置 SQLite，零依赖）

```bash
node <脚本> init <companyRoot>                       # 建库建表（幂等，自动建 memory 目录/种子文件）
node <脚本> read <companyRoot> <客户id> [limit]       # 读客户档案 + 最近会话（对症下药）
node <脚本> log <companyRoot> <客户id> <in|out> <文本> # 追加会话留痕
node <脚本> update <companyRoot> <客户id> <档案摘要>    # 更新该客户工作记忆
node <脚本> list <companyRoot>                        # 一次拉取全部客户（含档案摘要）
node <脚本> stats <companyRoot>                       # 统计客户数/消息数
```

脚本路径：`<skill 资源基准>/../scripts/customer-memory.mjs`（用 pwsh 执行 `node <路径>`）。

## 三、记忆读写纪律（铁律）

**每条客户消息按此流程**：

1. **识别客户 id**：`open_id`（私聊）/ `chat_id`（群聊）。
2. **读三层**（回复前必读）：
   - 公司记忆 `company.md`（口径/近况）
   - 通用记忆 `general.md`（技巧/经验）
   - 该客户档案：`read <companyRoot> <客户id>`（无档案自动建档）
3. **对症回答**：结合该客户历史/偏好/情绪 + 公司口径 + 通用技巧，通过你的回复通道（如 feishu_send）回复。
4. **分类写**（回复后必做）：
   - 会话：`log <companyRoot> <客户id> in|out <文本>`
   - 客户档案：`update <companyRoot> <客户id> <摘要>`（偏好/诉求/情绪/进展/待办）
   - 公司相关新信息（项目进度/政策）：追加 `company.md`
   - 通用技巧/踩坑（去敏）：追加 `general.md`

**隔离铁律**：只读写**自己的客户 id**；绝不把客户 A 的信息写进客户 B；公司/通用记忆共享，客户档案隔离。

### 群聊归并（同一客户跨群/跨私聊自动对应）

群消息（`oc_`）附**群内发言者 open_id**（`【归并】` 行）：

1. `log <companyRoot> <群chat_id> in|out <文本> <发言者open_id>` —— 既记**群档案**（chat_id，保留群视图），又自动归并到**客户主档案**（open_id），并在主档案 `group_ids` 记录客户出现在哪些群。
2. `read <companyRoot> <客户open_id>` —— 显示该客户**跨群/私聊合并的历史** + 所在群列表：客服接手时知道这客户在群 A、群 B、私聊都聊过什么。
3. 效果：同一客户在不同群聊天、或群聊+私聊，都能对应为**同一份客户档案**，信息不割裂。

## 四、自主判断推送（配合使用）

- 承诺了"稍等/核实后回复" → 完成后**主动推送**结果（不等对方追问）；未完成 → 记待办进客户档案，下次输出再判断。
- 重大决策（定价/退款/承诺/超范围）→ **不自行决定**，升级老板 → 老板征询用户（真人）拍板后才执行。

## 五、验收标准（对客岗位通用）

- [ ] 回复前已读三层（company.md + general.md + 该客户档案）
- [ ] 回复后已分类写（log + update；公司/通用信息进对应记忆）
- [ ] 客户档案按 id 隔离：绝不跨客户读写
- [ ] 承诺必兑现：完成即主动推送
- [ ] 重大决策升级真人拍板，未授权不承诺
